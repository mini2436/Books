# Private Reader 接口文档

## 1. 说明

当前后端接口以 REST 为主，默认本地地址为：

- `http://localhost:8080`
- 业务接口统一位于 `/api` 下

鉴权方式：

- 登录后获得 `accessToken`
- 需要登录的接口在请求头中传入：

```http
Authorization: Bearer <accessToken>
```

角色说明：

- `SUPER_ADMIN`：超级管理员，可管理用户、角色和全部后台能力
- `LIBRARIAN`：馆员，可管理图书、扫描源、批注和书签
- `READER`：读者，仅访问自己的阅读、同步和授权书籍

统一响应：

- 成功：返回 JSON 或文件流
- 错误：默认返回 `{"error":"..."}` 或 `{"message":"..."}` 等 JSON

## 2. 认证接口

### 2.1 登录

- 方法：`POST`
- 路径：`/api/auth/login`
- 是否需要登录：否

请求体：

```json
{
  "username": "admin",
  "password": "admin12345"
}
```

响应示例：

```json
{
  "accessToken": "....",
  "refreshToken": "....",
  "user": {
    "id": 1,
    "username": "admin",
    "role": "SUPER_ADMIN"
  }
}
```

### 2.2 刷新令牌

- 方法：`POST`
- 路径：`/api/auth/refresh`
- 是否需要登录：否

请求体：

```json
{
  "refreshToken": "...."
}
```

说明：

- 使用 `refreshToken` 换取新的 `accessToken` 和 `refreshToken`
- 原刷新令牌会被撤销

### 2.3 退出登录

- 方法：`POST`
- 路径：`/api/auth/logout`
- 是否需要登录：是

说明：

- 会撤销当前 `Authorization` 对应的 access token

响应示例：

```json
{
  "success": true
}
```

## 3. 阅读端接口

### 3.1 获取我的书架

- 方法：`GET`
- 路径：`/api/me/books`
- 是否需要登录：是

说明：

- `SUPER_ADMIN` 和 `LIBRARIAN` 默认可访问全部书籍
- `READER` 仅返回被显式授权的书籍

返回字段：

- `id`
- `title`
- `author`
- `description`
- `pluginId`
- `format`
- `sourceType`
- `granted`
- `sourceMissing`
- `updatedAt`

### 3.2 获取单本书详情

- 方法：`GET`
- 路径：`/api/me/books/{bookId}`
- 是否需要登录：是

说明：

- 只有拥有该书访问权限的用户才能访问
- 详情接口会返回移动端统一正文阅读所需字段

响应示例：

```json
{
  "id": 12,
  "title": "示例图书",
  "author": "作者",
  "description": "简介",
  "pluginId": "plugin-epub",
  "format": "epub",
  "sourceType": "MANAGED_UPLOAD",
  "manifest": {
    "format": "epub",
    "toc": [
      { "title": "第一章", "href": "chapter-0" }
    ],
    "primaryLocation": "chapter-0"
  },
  "capabilities": ["READ_ONLINE"],
  "sourceMissing": false,
  "hasStructuredContent": true,
  "contentModel": "UNIFIED_V1",
  "latestContentVersionId": 31
}
```

### 3.3 获取阅读 manifest

- 方法：`GET`
- 路径：`/api/me/books/{bookId}/content-manifest`
- 是否需要登录：是

说明：

- 返回插件生成的阅读导航结构
- Web 旧阅读链路仍会消费该接口
- 如果插件没有生成 manifest，可能返回 `null`

### 3.4 获取统一正文目录

- 方法：`GET`
- 路径：`/api/me/books/{bookId}/content`
- 是否需要登录：是

用途：

- 判断该书是否存在统一正文
- 获取章节摘要列表，供移动端做目录与章节懒加载

响应示例：

```json
{
  "bookId": 12,
  "contentModel": "UNIFIED_V1",
  "contentVersionId": 31,
  "hasStructuredContent": true,
  "chapters": [
    {
      "chapterIndex": 0,
      "title": "第一章",
      "anchor": "chapter-0"
    }
  ]
}
```

### 3.5 获取统一正文单章

- 方法：`GET`
- 路径：`/api/me/books/{bookId}/content/chapters/{chapterIndex}`
- 是否需要登录：是

用途：

- 章节懒加载
- 目录定位后按需加载正文块

响应示例：

```json
{
  "bookId": 12,
  "contentModel": "UNIFIED_V1",
  "contentVersionId": 31,
  "hasStructuredContent": true,
  "chapterIndex": 0,
  "title": "第一章",
  "anchor": "chapter-0",
  "blocks": [
    {
      "blockIndex": 0,
      "type": "paragraph",
      "anchor": "chapter-0-block-1",
      "text": "正文内容",
      "plainText": "正文内容",
      "meta": {}
    }
  ]
}
```

说明：

- 当前块类型主要包括：`heading`、`paragraph`、`quote`、`divider`
- 移动端首期统一正文阅读器主要面向 `TXT / EPUB`

### 3.6 获取原始文件

- 方法：`GET`
- 路径：`/api/me/books/{bookId}/file`
- 是否需要登录：是

说明：

- 返回服务器上的原始文件流
- 用于 Web 旧阅读链路和 PDF 回退链路

### 3.7 获取封面

- 方法：`GET`
- 路径：`/api/me/books/{bookId}/cover`
- 是否需要登录：是

说明：

- 有封面时返回图片流
- 无封面时返回 `204`

### 3.8 获取正文资源

- 方法：`GET`
- 路径：`/api/me/books/{bookId}/content/resources/{resourceId}`
- 是否需要登录：是

说明：

- 返回结构化正文或 manifest 中引用的二进制资源
- 当前主要用于图片等内嵌资源
- 找不到资源时返回 `404`

## 4. 同步接口

### 4.1 推送离线变更

- 方法：`POST`
- 路径：`/api/me/sync/push`
- 是否需要登录：是

请求体字段：

- `annotations`：批注变更
- `bookmarks`：书签变更
- `progresses`：阅读进度变更

批注 action：

- `CREATE`
- `UPDATE`
- `DELETE`

示例：

```json
{
  "annotations": [
    {
      "clientTempId": "anno-local-1",
      "bookId": 12,
      "action": "CREATE",
      "quoteText": "example quote",
      "noteText": "my note",
      "color": "#C3924A",
      "anchor": "chapter-0-block-1",
      "updatedAt": "2026-04-18T12:00:00Z"
    }
  ],
  "bookmarks": [],
  "progresses": []
}
```

响应字段：

- `annotationMappings`：客户端临时批注 ID 到服务端 ID 的映射
- `conflicts`：版本冲突列表

说明：

- 新移动端默认使用统一正文 anchor
- 批注更新会校验 `baseVersion`，版本不一致会返回冲突

### 4.2 拉取增量同步数据

- 方法：`GET`
- 路径：`/api/me/sync/pull`
- 是否需要登录：是

查询参数：

- `cursor`：上次同步完成时拿到的时间游标，单位毫秒，可选

响应字段：

- `cursor`
- `annotations`
- `bookmarks`
- `progresses`

### 4.3 获取某本书的批注

- 方法：`GET`
- 路径：`/api/me/books/{bookId}/annotations`
- 是否需要登录：是

说明：

- 返回当前用户在该书上的批注列表

### 4.4 获取某本书的书签

- 方法：`GET`
- 路径：`/api/me/books/{bookId}/bookmarks`
- 是否需要登录：是

说明：

- 返回当前用户在该书上的书签列表

### 4.5 更新阅读进度

- 方法：`PUT`
- 路径：`/api/me/books/{bookId}/progress`
- 是否需要登录：是

请求体示例：

```json
{
  "bookId": 12,
  "location": "chapter-0",
  "progressPercent": 42.5,
  "updatedAt": "2026-04-18T12:10:00Z"
}
```

说明：

- 路径中的 `bookId` 必须和请求体中的 `bookId` 一致

## 10. 备份与恢复接口

以下接口均要求 `SUPER_ADMIN`。备份文件为 ZIP；系统备份同时包含数据库内容、缓存资源和当前可读取的书籍原文件。恢复系统备份会替换当前系统数据，并撤销所有已登录会话。

### 10.1 导出备份

- 方法：`GET`
- 路径：`/api/admin/backups/export`
- 范围：`FULL`（默认，完整系统）、`BOOKS`（书籍及文件）或 `USER_DATA`（用户阅读数据）

选择参数：

- `BOOKS` 可重复传入 `bookIds`；不传时导出全部书籍。
- `USER_DATA` 必须传入至少一个 `userIds`，可用 `bookIds` 限定书籍。
- `USER_DATA` 可重复传入 `dataTypes`：`BOOK_ACCESS`、`BOOK_GROUPS`、`ANNOTATIONS`、`BOOKMARKS`、`READING_HISTORY`、`READING_PROGRESS`；不传时包含全部类型。

`USER_DATA` 不备份用户密码或账号 ID；书籍通过 `book_files.file_hash` 标识，以便跨系统匹配同一本书。

`BOOKS` 包含书籍元数据、封面、结构化正文、资源缓存和当前可读取的原文件。`USER_DATA` 不备份密码，也不会在目标系统直接沿用来源用户 ID；书籍通过 `book_files.file_hash` 跨系统匹配。

### 10.2 预览备份

- 方法：`POST`
- 路径：`/api/admin/backups/preview`
- 类型：`multipart/form-data`，字段名 `file`

返回 v2 备份范围、创建时间、来源用户、所含数据类型，以及书籍、批注、书签、阅读历史和进度数量。恢复前必须先预览；`FULL` 与 `USER_DATA` 包可结合 `GET /api/admin/users`，只映射需要恢复的来源用户。

### 10.3 恢复备份

- 方法：`POST`
- 路径：`/api/admin/backups/restore?operationId=restore-...`
- 类型：`multipart/form-data`
- 文件字段：`file`
- 恢复计划字段：`request`（`application/json`，必填）

备份包表示“最多可恢复的内容”，`request.scope` 表示本次实际恢复范围。`FULL` 包可选择 `FULL`、`BOOKS` 或 `USER_DATA`；`BOOKS` 与 `USER_DATA` 包只能恢复自身范围。

```json
{
  "scope": "USER_DATA",
  "userMappings": {
    "101": 8
  },
  "mode": "REPLACE",
  "dataTypes": ["BOOKMARKS", "READING_HISTORY"]
}
```

- `scope=FULL` 会替换完整系统并撤销所有登录会话，不接受用户映射或数据类型筛选。
- `scope=BOOKS` 只导入书籍、正文缓存和原文件；即使文件来自 `FULL` 包，也不会覆盖用户或阅读数据。
- `scope=USER_DATA` 必须提交至少一个 `userMappings`，其含义是“备份源用户 ID → 当前系统目标用户 ID”；未映射的来源用户不会恢复，必要时允许多个来源用户合并到同一目标用户。
- `dataTypes` 只允许选择备份包含的类型；不传时恢复包内全部用户数据类型。
- `MERGE` 只合并勾选类型的内容，并保留更新时间较新的阅读历史与进度；`REPLACE` 只清除“已映射用户 + 已勾选数据类型 + 备份涉及书籍”的交集，其他用户和未勾选类型不受影响。
- 找不到同一文件哈希的目标书籍时，不会将数据错误绑定到其他书籍，结果中的 `skippedBooks` 会计数提示。
- `BOOKS` 恢复按 SHA-256 去重并校验原文件大小与哈希，相同原文件不会重复导入。

### 10.4 查询恢复进度

- 方法：`GET`
- 路径：`/api/admin/backups/restore-status/{operationId}`

返回上传之后的校验、数据库、书籍文件、收尾、完成或失败状态，以及百分比和当前文件计数。

## 11. 权限规则

- `/api/auth/login`、`/api/auth/refresh` 匿名可访问
- `/api/auth/logout` 需要登录
- `/api/me/**` 需要登录
- `/api/admin/users/**` 仅 `SUPER_ADMIN` 可访问
- `/api/admin/**` 仅 `SUPER_ADMIN` 或 `LIBRARIAN` 可访问
- 书籍详情、manifest、统一正文、文件、封面和内容资源都要求用户拥有该书访问权限

## 12. 当前已知限制

- 统一正文阅读支持 `TXT / EPUB / FB2 / MOBI`，CBZ 以每张图片一个章节的方式分页
- `PDF` 使用独立的固定版面阅读路径
- MOBI 支持无 DRM 的未压缩或 PalmDOC 压缩文件；DRM 与 HUFF/CDIC 压缩会被明确拒绝
- 统一正文会保留常用文本块和图片，但不保证复杂 CSS、字体和固定版面完全还原
- 接口文档当前仍是手工维护版，后续可补 OpenAPI / Swagger
